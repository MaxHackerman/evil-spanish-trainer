# Evil Spanish 😈

Дикий тренажёр испанского языка: задания, проверка с подсветкой и объяснением ошибок, работа над ошибками и интервальное повторение. Поддерживает два варианта языка: испанский Испании и Латинской Америки.

## Как устроено занятие

1. Выполняешь пачку заданий без подсказок.
2. Жмёшь «Проверить» и получаешь отчёт: что верно, что почти верно (например, забыто ударение), где ошибка. Неверные буквы и слова подсвечены, к каждой ошибке есть объяснение: не то лицо глагола, не тот артикль, забытая смена гласной и т. д.
3. «Исправить ошибки»: задания с ошибками возвращаются, плюс новые задания на то же правило. Круг повторяется, пока всё не будет верно.
4. Тема уходит в интервальное повторение: ошибся — вернётся завтра; справился — через 1, 3, 7, 14, 30 дней.

## Публикация сайта (один раз)

1. На GitHub открой репозиторий → **Settings** → **Pages**.
2. В блоке **Build and deployment** выбери **Source: GitHub Actions**.
3. После каждого push в ветку `master` сайт сам проверится, соберётся и опубликуется (вкладка **Actions** показывает ход). Адрес: `https://maxhackerman.github.io/evil-spanish-trainer/`.

## Запуск на своём компьютере

Нужен Node.js 22.18 или новее.

```bash
npm install       # один раз
npm run dev       # сайт с автообновлением: откроется адрес вида http://localhost:5173
npm run check     # проверка типов, тесты и проверка контента
```

## Как добавить урок

Код трогать не нужно, весь контент лежит в `public/data/`:

- `lessons/<id>.json` — урок и его задания;
- `rules/<id>.json` — страница правила;
- `verbs.json` — словарь глаголов (для спряжения);
- `index.json` — список уроков и правил на главной.

Типы заданий: `conjugate` (спряжение), `choice` (выбор ответа), `text` (ввод текста), `picture` (что на картинке, с артиклем), `order` (собрать фразу из слов). Примеры — в существующих уроках.

После правок запусти `npm run validate-content`: скрипт проверит структуру и то, что правильный ответ каждого задания действительно принимается проверкой. То же самое автоматически делает GitHub перед публикацией, так что сломанный урок на сайт не попадёт.

## Архитектура

```
src/
  core/       — логика без привязки к браузеру: спряжение, проверка, диагностика ошибок,
                интервальное повторение, цикл занятия, валидация контента
  services/   — сменные «адаптеры»: хранилище, пользователь, доступы к функциям, ИИ, контент, озвучка
  i18n/       — все тексты интерфейса и объяснений (сейчас русский)
  ui/         — экраны и обработка действий
public/data/  — учебный контент (JSON)
tests/        — тесты ядра и экранов
scripts/      — проверка контента
```

Задел на масштабирование: интерфейс и ядро не обращаются напрямую ни к хранилищу браузера, ни к серверу, только через сервисы из `src/services/container.ts`. Чтобы перейти на аккаунты, облачную синхронизацию, платные функции или ИИ-режимы, меняются реализации сервисов, а не весь код:

| Сервис | Сейчас | Потом |
|---|---|---|
| `KeyValueStore` | хранилище браузера | облачная база (например, Supabase) |
| `AuthService` | один локальный пользователь | регистрация и вход |
| `Entitlements` | всё доступно | проверка подписки |
| `AiService` | выключен | сервер-посредник к языковой модели |
| `ContentRepository` | JSON-файлы | база данных или API |

Важно: GitHub Pages подходит для личного использования, но по правилам GitHub не предназначен для коммерческих сервисов. При монетизации сайт переносится на другой хостинг (Cloudflare Pages, Vercel, Netlify) без изменений в коде.

## Источники контента

Объяснения правил написаны специально для проекта. Картинки в заданиях — системные эмодзи. Для изображений из других источников в данных есть поля `credit` и `license`: используем только то, что разрешено лицензией.
